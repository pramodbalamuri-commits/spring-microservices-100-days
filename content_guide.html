Learning Roadmap · 100 Days

Java · Spring · Spring Boot Microservices

The complete content guide behind the 100-day schedule. One topic a day, each with a real-time "ShopFast" scenario, a learn task, and a build task — ending in a full microservices capstone you can demo.

How this works. ~1.5–2 hours a day: ≈45 min learn the concept → ≈45 min build something that runs → ≈15 min notes + commit. Each day lives in its own file (days/day-001.md … day-100.md) on GitHub; the dated SCHEDULE.md links them in order. Every day opens with a real-time ShopFast scenario — a running story of building one online-order platform — so the concept always attaches to a real system, not an abstract snippet.

What you'll learn to do (outcomes)

  • Stand up a secured, tested, documented Spring Boot REST service on a real database.
  • Decompose a system into microservices and wire them with the Spring Cloud stack.
  • Make services resilient (circuit breakers, retries, timeouts) and loosely coupled with events.
  • Observe them (metrics, logs, traces), containerize them, and deploy to Kubernetes via CI/CD.
  • Reason about the hard parts — distributed data, idempotency, sagas, eventual consistency.

The ShopFast throughline

Every day's scenario is a chapter in building ShopFast, an online-order platform. Early days add plain-Java logic (order classification, wallets, pricing); the middle builds its REST API and database; later days split it into product / order / payment services behind a gateway, add an OrderPlaced event stream, and ship it on Kubernetes. By Day 95 the whole system comes up with one command. This continuity is deliberate: you're not learning 100 disconnected tricks — you're watching one real system grow from a main() method to a cloud-deployed microservices platform.

Daily rhythm & rules

  1. Code every day — one runnable thing. Momentum beats marathon sessions.
  2. Commit daily — the repo doubles as your portfolio and your proof of consistency.
  3. Fill the 3-line note (learned / built / confusing) in each day file — future-you will thank you.
  4. Fell behind? Don't reset the calendar — just continue at the next topic. Order matters, dates don't.
  5. Use Claude Code as your pair — ask it to explain a concept, review your code, or debug a failure.
Adjust freely. The schedule is calendar-sequential from the start date; it doesn't skip weekends. Treat weekends/holidays as buffer or review — the point is 100 topics in order, not 100 consecutive calendar days. Re-run generate_days.py with a new START_DATE to re-date everything.
